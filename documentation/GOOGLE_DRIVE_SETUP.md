# Подключение Google Drive — v96

## Что используется

- GitHub Pages: панель и публичный `report.html`.
- Firebase Auth: вход пользователя через Google.
- Firestore: профиль, прогресс и метаданные файлов.
- Google Drive API: изображения, аватар и JSON публичного отчёта.

Платный сервер и Vercel Blob не используются.

## Настройка проекта

1. Открыть Google Cloud Console.
2. Выбрать проект `rp-cabinet`, связанный с текущим Firebase.
3. APIs & Services → Library → найти **Google Drive API** → Enable.
4. Google Auth Platform → Data Access → Add or remove scopes.
5. Добавить:

   `https://www.googleapis.com/auth/drive.file`

6. В Audience:
   - для тестирования добавить аккаунты в Test users;
   - для всех пользователей перевести приложение в Production после настройки бренда.
7. В Clients открыть Web client, который использует Firebase Google Auth.
8. Добавить origin GitHub Pages, например:

   `https://wxzg4bgc6n-code.github.io`

9. Credentials → API Keys → открыть ключ, используемый в `js/config/google-drive.js`.
10. Application restrictions: Websites.
11. Добавить адрес панели:

    `https://wxzg4bgc6n-code.github.io/*`

12. API restrictions: разрешить Google Drive API. Если этот ключ уже ограничен Firebase API, добавить Drive API в список либо создать отдельный браузерный ключ и заменить только `apiKey` в `js/config/google-drive.js`.

Client secret в GitHub загружать нельзя. Для текущей браузерной модели он не нужен.

## Первая проверка

1. Опубликовать v96 через GitHub Pages.
2. Войти через Google.
3. Подтвердить дополнительное разрешение на файлы Google Drive.
4. В Google Drive проверить папки:

   - `RP CABINET/Скриншоты`;
   - `RP CABINET/Отчёты`;
   - `RP CABINET/Аватар`.

5. Отметить требующий доказательства пункт.
6. Загрузить изображение.
7. Открыть панель на втором устройстве под тем же аккаунтом.
8. Проверить появление метаданных и изображения.
9. Завершить ступень и сформировать отчёт.
10. Открыть ссылку в режиме инкогнито: вход Google запрашиваться не должен.
11. Проверить увеличение изображения внутри отчёта.
12. Загрузить и заменить аватар; в папке `Аватар` должен остаться один актуальный файл.

## Безопасность

- `drive.file` не даёт панели читать произвольные файлы пользователя.
- Панель видит только файлы, созданные или открытые через неё.
- Скриншот публикуется как `anyone / reader`, но `allowFileDiscovery=false`.
- Папки Google Drive публичными не становятся.
- Публичный API key ограничивается доменом GitHub Pages и Drive API.
- OAuth access token хранится только в памяти и `sessionStorage`.
- После истечения токена Google может попросить кратко переподключить Диск.

## Очистка

Google Drive не поддерживает правило удаления «через 8 дней» для обычных файлов. Поэтому панель запускает очистку:

- после получения Drive access token;
- при ручном подключении Диска;
- перед дальнейшей работой с файлами.

Просроченные скриншоты и JSON отчётов удаляются окончательно, без корзины. Если пользователь долго не открывает панель, очистка произойдёт при следующем подключении.

Аватар в очистку не входит. При загрузке нового аватара предыдущий удаляется отдельно.

## Публичный отчёт

Ссылка имеет вид:

`report.html?id=<DRIVE_FILE_ID>&rk=<RESOURCE_KEY>`

`report.html` получает публичный JSON через Google Drive API key, строит карточки заданий и загружает публичные изображения. В отчёте нет перехода в основную панель.
