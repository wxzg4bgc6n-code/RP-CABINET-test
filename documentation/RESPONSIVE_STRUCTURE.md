# Разделение общего и мобильного кода — v97

Проверены все локальные HTML, CSS и JavaScript-файлы сборки. ПК и телефон используют одну разметку, одни данные и одну бизнес-логику.

## Куда вносить изменения

| Область | Файл | Решение |
|---|---|---|
| Общая оболочка и темы | `css/core.css` | Общие правила; существующие локальные breakpoints компонентов сохранены для совместимости |
| Общий вид умного поиска | `css/features/smart-context-search.css` | Без мобильных `max-width`-блоков |
| Мобильная оболочка панели | `css/responsive/mobile.css` | Профиль, нижняя навигация, мобильные модальные окна и мобильный вид поиска |
| Общая логика поиска | `js/features/smart-context-search.js` | Один индекс и одно поведение для ПК и телефона |
| Реакция оболочки на экран | `js/features/mobile-navigation.js` | Высота viewport, мобильные классы и поведение нижней навигации |
| Данные и тексты | `data/` | Никогда не копируются в мобильный модуль |
| Firebase и профиль | `js/app.js`, `js/core/realtime-state.js` | Общая логика, не зависит от устройства |
| Отдельная страница отчёта | `report.html`, `css/report.css`, `js/report.js` | Самостоятельная страница; её адаптация остаётся рядом с отчётом |

## Сохранено из v92

- показ шестого пункта «Поиск» в нижней панели;
- шесть колонок мобильной нижней навигации;
- полноэкранный мобильный диалог поиска;
- мобильные отступы, размеры и одноколоночный фильтр;
- компактные подписи «Открыть/Закрыть» на очень узком экране.
- полноразмерное состояние `.filter-open`: результаты скрыты, а список областей занимает оставшуюся высоту.

Всё перечисленное теперь находится в `css/responsive/mobile.css`. Этот файл подключается после общего CSS поиска.

## Что намеренно не переносилось

Breakpoints внутри `tests.css`, `progress-proofs.css`, `usaf-law.css`, `usaf-speech.css`, `pinned-materials.css` и `surfaces.css` описывают внутреннюю адаптацию своих компонентов, а не отдельную мобильную оболочку. Они остаются рядом с компонентом, чтобы его стили не разделялись между несвязанными файлами.

`report.css` также остаётся самостоятельным: `report.html` не подключает основной `main.css`, поэтому перенос его мобильных правил в `mobile.css` сломал бы адаптацию публичного отчёта.

## Правило для следующих изменений

Если меняется только расположение элемента на телефоне — правка идёт в `css/responsive/mobile.css`. Если меняется внешний вид или поведение функции на всех устройствах — правка идёт в файл этой функции. Данные, Firebase и поисковый индекс никогда не дублируются по устройствам.
