RP CABINET v92 — КРАТКАЯ ПАМЯТКА

1. На GitHub загружать всё содержимое папки v92, включая index.html, report.html, assets, css, data, js, documentation, proof-service, _tools, README.md и build-summary.json.
2. Не загружать proof-service/node_modules и локальные .env/.env.local.
3. Телефон и ПК должны быть авторизованы в одном Google-аккаунте.
4. Firebase после Google-входа — единственный источник актуального профиля.
5. Канонический документ: users/{uid}/profiles/default_realtime.
6. При запуске и обновлении сначала выполнять get({source: "server"}); локальный кэш не отправлять.
7. onSnapshot должен оставаться подключённым всё время открытой страницы.
8. Синхронизировать точечными update(), а не полной заменой state.
9. Одна галочка = один путь progress.<context>.tasks.<task>.
10. Снятие галочки = FieldValue.delete() только этого пути.
11. Разные поля и галочки не должны перетирать друг друга.
11.1. Закрепления и выбранные активности калькулятора премии тоже входят в каноническое облачное состояние.
12. Не возвращать js/core/sync-merge.js, mutation-queue, syncRevision guards или сравнение локального updatedAt.
13. Кодирование ключей находится в js/core/realtime-state.js.
14. localStorage — только кэш и резервная копия; он не выбирает победителя.
15. Офлайн-очередью управляет Firestore IndexedDB, а не RP CABINET.
16. При visibilitychange/online можно только перечитать сервер; запрещено автоматически сохранять кэш.
17. Статус «Синхронизация активна» показывать только после серверного snapshot.
18. Ступени менять в data/levels.js, задания — в data/progress/.
19. Название опубликованного задания не менять без миграции: оно является ключом прогресса.
20. На один пункт разрешено любое количество оригинальных скриншотов; один файл — до 15 МБ.
21. Изображения не хранить в Firebase/Base64; синхронизируются только ссылки и метаданные.
22. Общий вид функций менять в css/core.css или css/features/; глобальную мобильную оболочку, нижнюю панель и мобильное размещение поиска — только в css/responsive/mobile.css.
23. При новой версии менять index.html, js/core/version.js, css/core.css, README, build-summary и документацию.
24. Проверка: галочка телефон → ПК, затем другая галочка ПК → телефон — обе должны остаться.
25. Проверка закрытого устройства: закрыть телефон, изменить ПК, открыть телефон — телефон получает Firebase и ничего не отправляет назад.
26. Проверка обновления: обновить телефон несколько раз — состояние ПК не должно измениться.
27. После публикации полностью заменить файлы репозитория и закрыть все старые вкладки панели.
28. Памятка USAF по УАК/ПК находится в data/usaf/law-guide.js и подключается после data/usaf/content.js.
29. Не добавлять номера статей УАК/ПК без проверки действующей редакции законодательства конкретного сервера.
30. Для USAF 5 → 6 материал `usaf-law` должен автоматически находиться в «Материалах для повышения».
31. Раскрытые блоки сохраняются в sessionStorage под ключом rpCabinetOpenDetails_v92 и восстанавливаются после возврата во вкладку.
32. Дефолтные материалы USAF формируются по порядку заданий прогресса; задания без отдельного точного материала пропускаются.
33. Ручные закрепления не заменяются и не сортируются автоматическим подбором.
34. SWIFT, FROGGER, Miljet и пилотирование не связывать с общим экзаменом по воздушной технике без отдельного точного материала.
35. В README хранить историю только трёх последних версий.
36. Создание отчёта прекращать через 20 секунд и возвращать кнопку в обычное состояние.
37. Загрузка готового отчёта: до 10 секунд на попытку, одна повторная попытка и кнопка «Попробовать снова».
38. В report.html сохранять независимый таймер на случай, если внешний report.js не загрузился.
39. Между всеми соседними пунктами готового отчёта должен быть видимый разделитель с номером следующего пункта.
40. Скрытый загрузчик отчёта должен иметь display:none даже при наличии у .report-state собственного display:grid.
41. В новый отчёт передавать HTTPS-аватар Google-профиля; при отсутствии или ошибке изображения показывать инициалы ника.
42. Старые отчёты без avatarUrl должны оставаться полностью совместимыми.
43. Дефолтную область поиска вычислять из актуальных S.org и S.section при каждом открытии окна.
44. Ранняя загрузка до Firebase не должна фиксировать пустую область: пока фильтр не ручной, USAF/Academy обновляются автоматически.
45. На телефоне поиск является шестым пунктом внутри .dashboard-tabs; отдельную fixed-кнопку поверх панели не добавлять.
46. Поисковый индекс формировать из существующих шаблонов Academy и USAF без копии учебных текстов.
47. Общий CSS поиска подключать до css/responsive/mobile.css, чтобы мобильные правила имели приоритет.
48. На ПК фильтр и результаты прокручиваются независимо. На телефоне открытие «Где искать» закрывает клавиатуру, скрывает результаты и отдаёт фильтру всё свободное место.
