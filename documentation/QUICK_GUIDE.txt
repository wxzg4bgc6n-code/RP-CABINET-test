RP CABINET v79 — КРАТКАЯ ПАМЯТКА

1. На GitHub загружать всё содержимое папки v79, включая report.html, css, data, js, documentation и proof-service.
2. Не загружать proof-service/node_modules и локальные .env/.env.local.
3. В GitHub Pages остаются index.html и report.html. Папка proof-service развёрнута отдельным проектом Vercel.
4. Рабочий API указан в js/config/proof-service.js: https://rp-cabinet-proof-service.vercel.app.
5. Тексты и тесты менять только в data/academy и data/usaf.
6. Ступени менять в data/levels.js, задания — в отдельных файлах data/progress/.
7. Название ступени в data/levels.js и data/progress/<отдел>.js должно совпадать полностью.
8. Не переименовывать опубликованное задание без необходимости: его текст является ключом сохранённой галочки.
9. Скриншот требуется только для участия в СО/специальной операции и ГМП.
10. На один пункт разрешено любое количество оригинальных скриншотов; один файл — до 15 МБ.
11. Не сохранять изображения в Firebase/localStorage и не превращать их в Base64.
12. Не обрезать и не сжимать скриншоты: в отчёте используется оригинальный файл.
13. Firebase после входа Google — единственный источник истины.
14. При запуске с Google сначала читать default_v79_realtime и только затем показывать панель.
15. Никогда не отправлять локальный кэш в облако только из-за открытия, обновления страницы или восстановления контрольной точки.
16. Синхронизировать только реальные пользовательские операции из js/core/sync-merge.js.
17. Галочка записывается операцией конкретного задания; снятие — явным false.
18. Firestore-транзакция всегда читает последнюю серверную ревизию перед наложением операций.
19. onSnapshot должен применяться для каждой новой syncRevision, независимо от устройства или вкладки-источника.
20. Входящий snapshot показывать вместе с ещё не подтверждённой локальной очередью, чтобы не было визуального отката.
21. Офлайн-очередь хранится в kiri:rp-cabinet:v79:mutation-queue и удаляется только после подтверждённой транзакции.
22. Старые default_v77/default и локальные ключи v77 используются только для одноразовой миграции.
23. Не возвращать сравнение локального/облачного updatedAt, «полноты профиля» или часов устройств.
24. Дату регистрации брать как самую раннюю корректную из account.createdAt и данных миграции; не использовать lastSync.
25. Общие стили менять в css/core.css или css/features/; мобильные — только в css/responsive/mobile.css.
26. Не создавать отдельный index для телефона и не дублировать тексты.
27. При новой версии менять номер в index.html, js/core/version.js, css/core.css, README, build-summary и памятке.
28. После публикации полностью заменить содержимое репозитория и один раз сделать Ctrl+F5 на ПК и телефоне.
29. Для проверки открыть ПК и телефон одновременно: галочка ПК → телефон, галочка телефон → ПК.
30. Затем закрыть телефон, изменить ПК, открыть телефон: телефон обязан получить облачное состояние и не отправить старый кэш обратно.
