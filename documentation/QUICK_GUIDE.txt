RP CABINET v75 — КРАТКАЯ ПАМЯТКА

1. На GitHub загружать всё содержимое папки v75, включая report.html, css, data, js, documentation и proof-service.
2. Не загружать proof-service/node_modules и локальные .env/.env.local.
3. В GitHub Pages остаются index.html и report.html. Папка proof-service развёрнута отдельным проектом Vercel.
4. Рабочий API указан в js/config/proof-service.js: https://rp-cabinet-proof-service.vercel.app.
5. Тексты и тесты менять только в data/academy и data/usaf.
6. Ступени менять в data/levels.js, задания — в отдельных файлах data/progress/.
7. Название ступени в data/levels.js и data/progress/<отдел>.js должно совпадать полностью.
8. Не переименовывать опубликованное задание без необходимости: его текст является ключом сохранённой галочки.
9. Скриншот требуется только для участия в СО/специальной операции и ГМП.
10. Правила обязательных скриншотов менять только в data/progress/proof-rules.js.
11. Общие стили менять в css/core.css или css/features/.
12. Мобильные размеры и расположение менять только в css/responsive/mobile.css.
13. Не создавать отдельный index для телефона и не дублировать тексты.
14. Не менять KEY, VERSION_KEY и PROFILE_BACKUP_KEY из js/core/storage-config.js.
15. Не сохранять изображения в Firebase/localStorage и не превращать их в Base64.
16. Не обрезать и не сжимать скриншоты: в отчёте используется оригинальный файл.
17. Не разрешать облачную запись до окончания загрузки профиля.
18. Снятие галочки должно записываться отдельной операцией false через queueProfileTaskSyncMutation.
19. Рабочий профиль сохраняется локально в основную и резервную копии, а в Firebase — в state и recoveryState.
20. Дату регистрации брать как самую раннюю корректную из account.createdAt, старых локальных копий и первого входа Firebase; не использовать lastSync/updatedAt.
21. Профиль с ошибочным ready:false восстанавливать, если в нём есть ник/исходный ник и данные карьеры или прогресса.
22. Не считать ник «Игрок» признаком пустого профиля.
23. До подтверждения облаком удерживать последнее нажатое состояние галочки через UI-lock в js/core/sync-merge.js.
24. Vercel проверяет Firebase ID token через Identity Toolkit; Firebase Admin и служебный JSON-ключ не использовать.
25. Проект Vercel должен быть связан с GitHub и иметь Root Directory proof-service.
26. Последний подтверждённый выбор организации, отдела и ступени хранить в отдельной контрольной точке; неполное локальное или облачное состояние не должно её перезаписывать.
27. Полный локальный профиль показывать сразу, а проверку Firebase выполнять в фоне.
28. Повторная отрисовка с той же целью прогресса не должна перезапускать анимацию круга.
29. На один пункт отчёта разрешать любое количество оригинальных скриншотов без фиксированного лимита.
30. При новой версии менять номер сразу в index.html, js/core/version.js, css/core.css, README, build-summary и памятке.
31. После публикации полностью обновить страницу на ПК и телефоне.
32. Перед включением пользователям проверить страницу GitHub Pages и Vercel без VPN с ПК и телефона.
