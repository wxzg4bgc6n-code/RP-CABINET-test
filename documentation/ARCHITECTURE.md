# Архитектура RP Cabinet v68

## Основной принцип

Один вид информации имеет одно место хранения. Основная вкладка, материалы текущего ранга и закреплённая копия используют общий шаблон из `data/`. ПК и телефон используют один HTML и одни данные.

## Порядок загрузки

1. `data/registry.js` и шаблоны отделов.
2. `js/core/template-loader.js`.
3. `js/core/version.js`, `js/core/storage-config.js`, `js/core/sync-merge.js`.
4. Списки отделов, ступени и задания прогресса.
5. `js/app.js` — состояние, рендер и Firebase.
6. `js/features/` — независимые функции интерфейса.
7. `js/features/mobile-navigation.js` — поведение только на узком экране.

Файлы данных всегда подключаются до `js/app.js`.

## Адаптивность без дублирования

- `index.html` общий для ПК и телефона.
- `css/responsive/mobile.css` подключается последним и имеет право переопределять только расположение, размеры, переносы и сенсорные состояния.
- `js/features/mobile-navigation.js` не содержит текстов Academy/USAF и не хранит профиль. Он только отмечает мобильный режим, обслуживает нижнюю навигацию и экранную клавиатуру.
- Новая информация никогда не копируется в мобильный файл.

На телефоне основная навигация закреплена снизу, карточка профиля компактная, многоколоночные блоки переходят в одну колонку, изображения сохраняют полный размер без обрезания, модальные окна учитывают высоту экранной клавиатуры.

## Модель синхронизации

`js/core/sync-merge.js` задаёт логические группы состояния и поле `syncFieldUpdatedAt` с отдельным временем изменения каждой группы.

Когда локальное состояние меняется, `save()` сравнивает его с последним локальным снимком и обновляет время только изменившихся групп. Когда приходит профиль другого устройства, `mergeSyncedProfileStates()` выбирает более новую версию каждой группы отдельно.

Пример конфликта:

- на ПК изменён ник;
- на телефоне позже отмечено задание USAF, но там остался старый ник;
- результат: новый ник берётся с ПК, новый прогресс — с телефона;
- объединённое состояние отправляется обратно в Firebase и становится общей актуальной версией.

Старые состояния без `syncFieldUpdatedAt` мигрируют автоматически: исходный `updatedAt` временно используется для всех групп.

## Сохранение

- `rp_panel_account_profile_STABLE` — основной профиль;
- `rp_panel_v156_fast_boot_safe_cache` — совместимый служебный ключ;
- номер интерфейса не меняет ключи хранения;
- прогресс хранится раздельно по проекту, пути, организации, отделу и ступени;
- выбранная ступень хранится отдельно для каждого отдела.

## Добавление нового отдела

1. Добавить отдел в `data/sections.js` и `data/registry.js`.
2. Добавить ступени в `data/levels.js`.
3. Создать `data/progress/<отдел>.js`.
4. Создать `data/<отдел>/content.js` и `data/<отдел>/tests.js`.
5. Подключить данные до `js/app.js`.
6. При необходимости создать общий стиль `css/features/<отдел>.css`.
7. Проверить вкладку, тесты, закрепление, ранги, прогресс, телефон и синхронизацию.

## Перед передачей версии

- проверить синтаксис всех JS;
- проверить существование CSS, JS и изображений;
- открыть ПК-ширину и телефонную ширину;
- сменить ник, перезагрузить страницу и убедиться, что он сохранился;
- проверить конфликт «ник на ПК / прогресс на телефоне»;
- проверить Academy, USAF, тесты, карты и закреплённые материалы;
- убедиться, что в консоли нет ошибок.
