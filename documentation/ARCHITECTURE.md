# Архитектура RP Cabinet v98

## Клиентская структура

- `index.html` — основная панель.
- `report.html` — отдельный публичный просмотр отчёта.
- `data/` — ступени, задания, информация и тесты.
- `js/app.js` — профиль, Firebase Auth и основная отрисовка.
- `js/core/realtime-state.js` — каноническая Firestore-модель и точечные операции.
- `js/services/google-drive-storage.js` — Drive OAuth token, папки, загрузка, доступ и очистка.
- `js/features/progress-proofs.js` — доказательства прогресса и манифест отчёта.
- `js/features/google-drive-avatar.js` — карандаш на аватаре, подготовка и безопасная замена фотографии.
- `js/report.js` — анонимное чтение публичного манифеста и изображений.
- `css/responsive/mobile.css` — мобильная оболочка.

## Источники истины

| Данные | Источник |
|---|---|
| Профиль, прогресс, настройки | Firestore `default_realtime` |
| Скриншоты | личный Google Drive пользователя |
| JSON публичного отчёта | личный Google Drive пользователя |
| Пользовательский аватар | личный Google Drive пользователя |
| Последний показанный кэш | localStorage |
| Drive access token | память вкладки и sessionStorage |

## Синхронизация

Модель v80 сохранена:

- Firebase является единственным источником состояния после Google-входа.
- `onSnapshot` постоянно принимает изменения.
- `update()` записывает только изменённые пути.
- открытие страницы, `visibilitychange` и `online` выполняют только серверное чтение;
- Firestore IndexedDB отвечает за офлайн-записи;
- собственной очереди операций нет.

Скриншоты синхронизируются не как бинарные данные. В Firestore передаются только `fileId`, `resourceKey`, URL и размеры. Поэтому телефон и ПК видят один список, а файл скачивается непосредственно с Google Drive.

## Авторизация Google Drive

Firebase Google Sign-In и Google Drive permission используют один Google-аккаунт, но являются разными разрешениями.

1. При ручном Google-входе `GoogleAuthProvider` запрашивает `drive.file`.
2. Firebase возвращает Google OAuth access token.
3. Токен передаётся в `GoogleDriveStorage.setAccessToken()`.
4. Токен не записывается в Firebase или localStorage.
5. После восстановления старой Firebase-сессии без OAuth token пользователь кратко переподключает Диск.

`drive.file` ограничивает панель файлами, созданными или открытыми через неё.

OAuth access token временный: он хранится в памяти вкладки и `sessionStorage`, а не в Firebase. Новый отчёт не требует нового разрешения, пока токен действует. После истечения токена или новой сессии браузера Google может запросить доступ повторно.

## Папки Google Drive

```text
RP CABINET/
├── Скриншоты/
├── Отчёты/
└── Аватар/
```

Папки ищутся и создаются с `appProperties.rpCabinetFolder`.

## Загрузка доказательства

1. Проверяется Google-вход и Drive token.
2. Проверяется MIME и лимит 15 МБ.
3. Читаются исходные размеры.
4. Файл загружается multipart-запросом прямо из браузера в папку `Скриншоты`.
5. Файлу назначается `anyone / reader`, `allowFileDiscovery=false`.
6. В Firebase записываются только метаданные.
7. В интерфейсе изображение читается через Drive API media URL.

## Удаление доказательств

- крестик остаётся у каждого скриншота всегда;
- при активном отчёте удаление отдельного файла сначала удаляет JSON отчёта;
- кнопка «Удалить все скриншоты» удаляет JSON отчёта и до четырёх файлов параллельно;
- ответ Drive `404` означает, что файл уже удалён, поэтому локальная запись также очищается;
- неподтверждённые удаления остаются в панели либо могут быть убраны только локально после отдельного подтверждения.

## Публичный отчёт

1. Собираются профиль, задания и ссылки на файлы.
2. Создаётся JSON версии 3.
3. JSON загружается в `RP CABINET/Отчёты`.
4. JSON получает публичное чтение по ссылке.
5. Пользователю выдаётся `report.html?id=...&rk=...`.
6. Получатель без входа загружает JSON и изображения через ограниченный API key.
7. В отчёте нет навигации в основную панель.

Карточки доказательств используют `drive.google.com/thumbnail` с шириной до 1100 px. Полноэкранный просмотр запрашивает миниатюру до 2400 px. Медленный `alt=media` остаётся резервом только на случай ошибки CDN.

Аватар отчёта восстанавливается последовательно:

1. Drive-миниатюра пользовательского аватара;
2. исходный Drive media URL;
3. отдельный `fallbackAvatarUrl` с Google-фото;
4. инициалы имени.

## Очистка

У скриншота и отчёта в `appProperties.expiresAt` записывается срок. При подключённом Drive token модуль просматривает только папки `Скриншоты` и `Отчёты`, после чего окончательно удаляет просроченные файлы.

Ручное удаление скриншота из прогресса не ждёт окончания срока: сначала вызывается Google Drive `files.delete`, затем запись удаляется из состояния профиля.

Аватар не имеет `expiresAt`. При замене:

1. новая WebP загружается;
2. метаданные сохраняются в Firebase;
3. старая фотография удаляется.

## Состояние аватара

`account.driveAvatar` синхронизируется как часть аккаунта:

```json
{
  "provider": "google-drive",
  "fileId": "...",
  "resourceKey": "...",
  "url": "...",
  "width": 512,
  "height": 512,
  "updatedAt": 0
}
```

Приоритет показа:

1. пользовательский Drive-аватар;
2. Google `photoURL`;
3. инициалы ника.

Редактор аватара не находится в настройках профиля. Он создаётся поверх `.avatar-wrap`: на ПК показывается при наведении или фокусе, а на сенсорных устройствах остаётся видимым.

После выбора файла открывается отдельный редактор. Минимальный масштаб всегда покрывает квадрат целиком, поэтому перемещение ограничено границами изображения и пустое пространство не попадает в итог. Выходной файл — WebP 512×512.

`renderProfileIcon()` сравнивает стабильный ключ файла и не пересоздаёт `<img>` при обычной перерисовке панели. Для только что загруженного файла используется локальный Object URL; для следующих сессий — Drive thumbnail с резервным media URL.

## Оптимизация скриншотов

Перед загрузкой браузер декодирует изображение один раз. Если исходник большой, он уменьшается до максимальной стороны 2560 px и сохраняется в WebP с качеством 0.84. Оригинал остаётся только тогда, когда преобразование не даёт выигрыша.

Прогресс меняет текст текущей кнопки без вызова полного `render()`. После успешной загрузки каждого отдельного файла его метаданные сохраняются и миниатюра появляется сразу.

В панели миниатюры читаются через Drive thumbnail или локальный Object URL. Нажатие открывает внутренний полноэкранный viewer; прямой переход на media URL не используется.

## Поиск и мобильная версия

Дефолтная область поиска вычисляется из актуальных `S.org` и `S.section`. Единственный запуск находится во вкладке «Поиск»; прежняя кнопка «Найти в материалах» удалена как дубликат. Мобильные переопределения находятся в `css/responsive/mobile.css`; фильтр использует оставшуюся высоту `100dvh`.
