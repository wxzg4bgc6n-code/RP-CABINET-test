# RP CABINET — TEST v97

## Что изменилось в v97

- Крестик удаления снова отображается у каждого скриншота, в том числе при активном публичном отчёте.
- Удаление одного скриншота при активном отчёте сначала отключает публичную ссылку, чтобы она не вела на неполный отчёт.
- Добавлена кнопка «Удалить все скриншоты» с количеством файлов.
- Массовое удаление удаляет активный JSON-отчёт и до четырёх скриншотов одновременно.
- Если отдельного файла уже нет на Google Диске, ответ `404` считается успешной очисткой и запись удаляется из панели.
- Если Google не подтвердил удаление, можно отдельно убрать зависшую запись только из панели.
- Файлы, которые не удалось удалить при массовой операции, не пропадают из интерфейса и остаются для повторной попытки.
- Временный OAuth access token сохраняется только в текущей сессии браузера. После его истечения или открытия новой сессии Google может снова запросить доступ; формирование каждого отчёта само по себе новый запрос не вызывает.

## Сохранено из v96

- Публичный отчёт больше не загружает полный оригинал для каждой карточки.
- В списке используется Drive-миниатюра до 1100 px, а в полноэкранном просмотре — до 2400 px.
- Исходный Google Drive media URL используется только при ошибке миниатюры.
- Добавлены предварительные соединения с Google Drive, чтобы первый файл открывался быстрее.
- Пока изображение загружается, показывается компактный индикатор без сдвига интерфейса.
- Аватар владельца отчёта сначала читается как Drive-миниатюра.
- Добавлена последовательность восстановления аватара: Drive-миниатюра → Drive media → Google-фото → инициалы.
- В новые JSON-отчёты отдельно записывается резервное Google-фото, поэтому ошибка пользовательского аватара не оставляет пустой значок.
- Старые отчёты с уже сохранённым `avatar.fileId` получают быстрый аватар без повторного формирования ссылки.

## Сохранено из v95

- Исправлена повторная загрузка аватара: `renderProfileIcon()` сохраняет существующий DOM-элемент, если файл не изменился.
- Новый Drive-аватар показывается через локальный предпросмотр сразу после загрузки.
- Если публичная ссылка Google ещё не успела активироваться, панель показывает резервное фото и делает только одну отложенную попытку без бесконечного мигания.
- После выбора фотографии открывается редактор кадра.
- Масштаб регулируется ползунком от 1× до 3×.
- Фотографию можно перемещать мышью или пальцем; пустое место за границей кадра недоступно.
- Итог сохраняется квадратным WebP 512×512 и всегда обрезается рамкой аватара.
- Скриншоты до отправки оптимизируются в WebP с максимальной стороной 2560 px, если это уменьшает файл.
- Процент загрузки обновляется без полной перерисовки раздела.
- Каждый скриншот появляется в панели сразу после собственной загрузки, не ожидая окончания всей пачки.
- Для новых файлов используется мгновенный локальный предпросмотр и уменьшенная Drive-миниатюра.
- Нажатие на скриншот открывает полноэкранный просмотр внутри панели; прямое скачивание по клику удалено.

## Обязательная настройка Google Cloud

Файлы v97 готовы, но Google не разрешит работу с Диском, пока API не включён в проекте.

1. Открыть Google Cloud Console и выбрать проект Firebase `rp-cabinet`.
2. Включить **Google Drive API**.
3. В OAuth consent screen → Data Access добавить scope:
   `https://www.googleapis.com/auth/drive.file`.
4. Убедиться, что домен GitHub Pages добавлен в Authorized domains и Authorized JavaScript origins текущего Web OAuth client.
5. В API key, указанном в `js/config/google-drive.js`, разрешить Google Drive API и ограничить использование доменом панели.
6. До публикации OAuth-приложения добавить нужные Google-аккаунты в список Test users.

Подробно: `documentation/GOOGLE_DRIVE_SETUP.md`.

## Синхронизация

После входа через Google единственным источником состояния профиля остаётся:

`users/{uid}/profiles/default_realtime`

Firebase хранит:

- профиль и карьерный контекст;
- галочки прогресса;
- закрепления и премию;
- `fileId`, `resourceKey`, размеры и названия скриншотов;
- идентификатор публичного отчёта;
- метаданные пользовательской аватарки.

Firebase не хранит изображения и Base64. Сами файлы принадлежат пользователю и находятся на его Google Диске.

Модель синхронизации v80 не изменена:

1. `onSnapshot` постоянно доставляет серверные изменения телефону и ПК.
2. Каждое действие обновляет только свой Firestore-путь.
3. Открытие или обновление страницы ничего не отправляет в облако.
4. Закрытое устройство сначала получает серверное состояние.
5. `localStorage` остаётся только кэшем.
6. Access token Google Drive не записывается в Firebase или постоянный `localStorage`.

## Скриншоты и отчёты

- PNG, JPG и WEBP;
- до 15 МБ на файл;
- без лимита количества на пункт;
- каждый файл сразу получает закрытую от поиска публичную ссылку;
- публичная ссылка не раскрывает папку или остальные файлы пользователя;
- ручное удаление скриншота из прогресса сразу вызывает Google Drive `files.delete`;
- крестик доступен у каждого скриншота, а кнопка «Удалить все скриншоты» очищает текущий контекст одной операцией;
- удаление скриншота при активном отчёте также удаляет JSON отчёта и отключает публичную ссылку;
- отсутствующий на Диске файл можно убрать из панели без зависания;
- оставленные скриншоты и отчёты автоматически очищаются через 8 дней при следующем подключении Диска;
- удаление отчёта вручную окончательно удаляет его JSON и связанные скриншоты;
- старые ссылки v92 не считаются активными отчётами v97.

## Аватар

- одна активная пользовательская фотография;
- центральное квадратное кадрирование;
- WebP 512×512;
- загрузка открывается карандашом поверх аватара, а не из настроек профиля;
- на ПК карандаш появляется при наведении, на телефоне виден постоянно;
- перед сохранением доступны масштабирование и перемещение кадра;
- новая фотография сначала загружается и синхронизируется, затем старая удаляется;
- аватар не участвует в восьмидневной очистке;
- если пользовательский аватар ещё не загружен, используется фото Google, затем инициалы.
