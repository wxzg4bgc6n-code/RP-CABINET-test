# RP CABINET — TEST v78

Снято фиксированное ограничение в 10 скриншотов на один пункт. Количество изображений теперь не ограничивается интерфейсом панели; ограничения размера отдельного файла и срок хранения не менялись.

# RP Cabinet v78 — неограниченное количество скриншотов

Актуальная тестовая версия панели на основе рабочей v77. Схема хранения профиля и облачный документ v77 сохранены без переименования, чтобы не потерять данные пользователей.

## Что изменилось в v78

- Убрано ограничение «до 10 файлов» на один пункт прогресса.
- Кнопка «Добавить ещё» остаётся доступной независимо от количества уже загруженных изображений.
- При выборе нескольких файлов загружается весь выбранный набор, а не только свободные места до лимита.
- В конфигурации `maxFilesPerTask: null` означает отсутствие фиксированного лимита количества.
- Ограничение одного изображения до 15 МБ, допустимые форматы PNG/JPG/WEBP и автоудаление через 8 дней сохранены.
- Номер панели, видимый бейдж, `TEST_VERSION`, `TEST_VERSION_LABEL` и cache-busting обновлены до v78.

## Сохранено из v77

- Полный локальный профиль имеет приоритет при запуске, поэтому старый облачный снимок не должен сбрасывать организацию и прогресс.
- Сообщение «Облако подключено» показывается только после подтверждённой записи Firestore.
- Единственный источник галочек — `progressByContext`; поле `tasks` остаётся временным зеркалом текущего экрана.
- Каждая отметка записывается отдельной операцией конкретного пункта.
- Постоянные локальные ключи и документ Firebase `default_v77` сохранены без изменения.

## Сохранено из v72

- Частично повреждённый облачный профиль восстанавливается по нику, исходному нику, организации, разделу, выбранному уровню и сохранённому прогрессу.
- Ник `Игрок` больше не считается пустым профилем и не вызывает повторный экран регистрации.
- Снятая или поставленная галочка блокируется в интерфейсе до подтверждения сервером, поэтому старый снимок другого устройства не вызывает мигание.
- Две стартовые подсказки системы скриншотов объединены в одну рамку.
- Vercel проверяет Firebase ID token через официальный Identity Toolkit и больше не требует отсутствующий служебный ключ Firebase Admin.
- Для Vercel-проекта рекомендуется подключить папку `proof-service` из этого GitHub-репозитория, чтобы сервер обновлялся вместе с панелью.

## Сохранено из v71

- Добавлены точные ступени и задания для Academy, MA, USAF, MP, DF, SD и ED.
- У USAF добавлены отсутствовавшие переходы 1→2, 2→3, 8→9 и 9→10.
- RAP и SAS не получили придуманных условий: в текущем Discord-файле отдельной системы повышения для них нет.
- Скриншот требуется только для пунктов участия в СО и ГМП.
- Остальные выполненные пункты остаются в отчёте без изображения и подтверждаются отметкой/тегом в Discord.
- Удалена лишняя подпись о появлении задач и исходном размере скриншота.
- Снятие галочки записывается как отдельное действие и не должно возвращаться из старого облачного снимка.
- Добавлена резервная локальная копия профиля и резервное состояние в Firebase.
- При запуске выбирается полноценный профиль, а неполный облачный снимок не должен сбрасывать пользователя на выбор организации.
- Дата регистрации восстанавливается по самой ранней корректной дате из профиля, старых локальных копий и даты первого входа Firebase.

## Что загружать на GitHub

В корень репозитория загружается **всё содержимое этой папки**, сохраняя структуру:

- `index.html`
- `report.html`
- `assets/`
- `css/`
- `data/`
- `js/`
- `documentation/`
- `proof-service/` без `node_modules`
- `README.md`
- `build-summary.json`

Папку `node_modules` и локальные секреты загружать нельзя.

## Где менять проект

| Общие стили и темы | `css/core.css`, `css/features/` |

## Как добавлять новые повышения

1. Добавить название ступени в массив нужного отдела в `data/levels.js`.
2. Добавить задания с абсолютно таким же названием ступени в `data/progress/<отдел>.js`.
3. Если создаётся новый файл отдела, подключить его в `index.html` после `data/progress/index.js`.
4. Не переименовывать уже опубликованные задания без необходимости: текст задания используется как стабильный ключ сохранённого прогресса.
5. Скриншоты назначаются централизованно в `data/progress/proof-rules.js`, а не внутри каждого списка.

## Синхронизация

Каждое изменение хранится как небольшая операция. Для снятой галочки в очередь записывается `false`, поэтому старое серверное значение не должно вернуть отметку. Облачная запись выполняется транзакцией поверх последнего состояния Firebase.

Профиль дополнительно сохраняется:

- в основном локальном ключе;
- в локальной резервной копии;
- в основном состоянии Firebase;
- в резервном состоянии Firebase.

Если один снимок неполный, панель выбирает более полноценный профиль. Подробности находятся в `documentation/ARCHITECTURE.md`.

## Сервис скриншотов

Сервис Vercel используется только для загрузки оригинальных изображений и формирования общей ссылки отчёта. Файлы не обрезаются и автоматически удаляются через 8 дней.

Адрес сервиса: `https://rp-cabinet-proof-service.vercel.app`
