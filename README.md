# RP CABINET — TEST v93

## Что изменилось в v93

- Vercel Blob и отдельная папка `proof-service` полностью удалены из сборки.
- Скриншоты каждого пользователя сохраняются на его личном Google Диске.
- Используется ограниченный OAuth scope `drive.file`: панель видит только созданные ею файлы.
- После Google-входа полученный Drive access token хранится только в памяти вкладки и `sessionStorage` до истечения срока.
- В Диске автоматически создаются папки `RP CABINET/Скриншоты`, `RP CABINET/Отчёты` и `RP CABINET/Аватар`.
- Количество скриншотов на пункт не ограничено; лимит отдельного файла остаётся 15 МБ.
- При подключённом Диске панель окончательно удаляет скриншоты и отчёты старше 8 дней.
- Отчёт сохраняется публичным JSON-файлом и открывается через обычный `report.html`.
- Получателю ссылки из Discord не требуется вход в Google.
- В отчёте фотографии показаны внутри оформленного интерфейса и увеличиваются без перехода в панель.
- В публичном отчёте нет кнопок и ссылок возврата в основную панель.
- Добавлена одна пользовательская аватарка 512×512 WebP. Новая фотография заменяет и удаляет предыдущую.
- Аватар хранится на Google Диске, синхронизируется через метаданные Firebase и показывается в шапке панели и отчёта.

## Сохранено из v92

- На телефоне раскрытие «Где искать» переводит поиск в полноразмерный режим фильтра.
- Экранная клавиатура закрывается перед раскрытием фильтра.
- Пока фильтр открыт, результаты не сжимают список областей поиска.
- Используется высота `100dvh`.

## Сохранено из v91

- «Где искать» остаётся отдельным заметным блоком над результатами.
- Фильтр использует цвета активной темы.
- Общие и мобильные стили поиска разделены.

## Обязательная настройка Google Cloud

Файлы v93 готовы, но Google не разрешит работу с Диском, пока API не включён в проекте.

1. Открыть Google Cloud Console и выбрать проект Firebase `rp-cabinet`.
2. Включить **Google Drive API**.
3. В OAuth consent screen → Data Access добавить scope:
   `https://www.googleapis.com/auth/drive.file`.
4. Убедиться, что домен GitHub Pages добавлен в Authorized domains и Authorized JavaScript origins текущего Web OAuth client.
5. В API key, указанном в `js/config/google-drive.js`, разрешить Google Drive API и ограничить использование доменом панели.
6. До публикации OAuth-приложения добавить нужные Google-аккаунты в список Test users.

Подробно: `documentation/GOOGLE_DRIVE_SETUP.md`.

## Синхронизация

После входа через Google единственным источником состояния профиля остаётся:

`users/{uid}/profiles/default_realtime`

Firebase хранит:

- профиль и карьерный контекст;
- галочки прогресса;
- закрепления и премию;
- `fileId`, `resourceKey`, размеры и названия скриншотов;
- идентификатор публичного отчёта;
- метаданные пользовательской аватарки.

Firebase не хранит изображения и Base64. Сами файлы принадлежат пользователю и находятся на его Google Диске.

Модель синхронизации v80 не изменена:

1. `onSnapshot` постоянно доставляет серверные изменения телефону и ПК.
2. Каждое действие обновляет только свой Firestore-путь.
3. Открытие или обновление страницы ничего не отправляет в облако.
4. Закрытое устройство сначала получает серверное состояние.
5. `localStorage` остаётся только кэшем.
6. Access token Google Drive не записывается в Firebase или постоянный `localStorage`.

## Скриншоты и отчёты

- PNG, JPG и WEBP;
- до 15 МБ на файл;
- без лимита количества на пункт;
- каждый файл сразу получает закрытую от поиска публичную ссылку;
- публичная ссылка не раскрывает папку или остальные файлы пользователя;
- отчёт и скриншоты очищаются через 8 дней при следующем подключении Диска;
- удаление отчёта вручную окончательно удаляет его JSON и связанные скриншоты;
- старые ссылки v92 не считаются активными отчётами v93.

## Аватар

- одна активная пользовательская фотография;
- центральное квадратное кадрирование;
- WebP 512×512;
- новая фотография сначала загружается и синхронизируется, затем старая удаляется;
- аватар не участвует в восьмидневной очистке;
- при удалении используется фото Google, затем инициалы.
