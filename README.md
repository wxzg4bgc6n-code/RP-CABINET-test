# RP CABINET — TEST v89

## Что изменилось в v89

- Добавлен полноценный умный поиск по материалам панели.
- По умолчанию область автоматически ограничена текущими организацией и отделом профиля.
- USAF ищет только по информации и тестам USAF, Academy — только по Academy.
- В скрытой панели «Где искать» добавлена иерархия `ГОСК / Крайм → организация → доступный отдел`; проекты намеренно отсутствуют.
- Доступные отделы можно выбирать одновременно, а организации без базы не создают пустых фиктивных материалов.
- Индекс строится напрямую из существующих DOM-шаблонов, поэтому отдельной копии текстов для поиска нет.
- Поиск работает во время ввода и учитывает заголовки, текст, вопросы, ответы, команды и числовые коды.
- Поддержан префиксный поиск кодов: `3` находит варианты `3.1`, `3.11`, `3-1` и похожие.
- Добавлены русские/английские сокращения и лёгкая устойчивость к окончаниям и опечаткам.
- Результат текущего отдела можно открыть прямо в панели: нужная вкладка включается, родительские блоки раскрываются, найденное место подсвечивается.
- Материалы другого отдела можно прочитать внутри результата без изменения отдела и прогресса профиля.
- На телефоне добавлена фиксированная кнопка «Поиск» и полноэкранная нижняя панель с крупным полем ввода.
- Цвета поиска полностью берутся из текущей темы через `var(--accent)`.
- Firebase-синхронизация, прогресс, скриншоты и отчёты не изменялись.

## Как добавлять новые повышения

1. Добавить название ступени в массив нужного отдела в `data/levels.js`.
2. Добавить задания с тем же названием ступени в `data/progress/<отдел>.js`.
3. Если для задания существует точный материал, добавить его сопоставление в `js/features/pinned-materials.js`.
4. Не связывать задание с общим экзаменом или памяткой только из-за похожих слов.
5. Задание без отдельного материала должно пропускаться.
6. Не переименовывать опубликованные задания без миграции: текст задания является ключом прогресса.
7. Правила скриншотов назначать в `data/progress/proof-rules.js`.

## Умный поиск

Поиск не хранит отдельную копию текстов. При запуске он строит индекс из существующих `<template>` Academy и USAF. Поэтому изменение исходного информационного блока или теста автоматически попадает в результаты.

Правила области поиска:

1. По умолчанию используется текущий контекст профиля: `путь → организация → отдел`.
2. В текущем USAF поиск охватывает информацию и тесты USAF; в Academy — информацию и тесты Academy.
3. Кнопка «Где искать» открывает расширенную структуру без выбора проекта: `ГОСК / Крайм → организация → доступный отдел`.
4. Организации без перенесённой базы отображаются в структуре, но не создают ложных результатов.
5. Доступные отделы можно выбирать одновременно.
6. Запрос применяется сразу при вводе; отдельная кнопка подтверждения не нужна.
7. Номера поддерживают префиксный поиск: запрос `3` находит `3.1`, `3.11`, `3-1` и другие подходящие записи.
8. Поиск проверяет заголовки, основной текст, вопросы, варианты ответов, команды и коды.
9. Для текущего отдела результат можно открыть прямо в панели; блок раскрывается и прокручивается к найденному месту.
10. Материал другого отдела показывается внутри поискового окна без изменения карьерного контекста профиля.
11. На телефоне используется фиксированная кнопка и полноэкранная нижняя панель.
12. Проект GTA5RP/Majestic RP в фильтры поиска не входит.

Чтобы добавить новый источник, зарегистрировать его `path`, `organization`, информационный шаблон и шаблон тестов в `data/registry.js`. Полный текст отдельно дублировать нельзя.

## Синхронизация

После входа через Google единственным источником актуального состояния является документ:

`users/{uid}/profiles/default_realtime`

Он хранит профиль, карьерный контекст, прогресс, выбранные ступени, закрепления, премию, метаданные скриншотов и ссылки отчётов.

Как работает синхронизация:

1. Телефон и ПК входят через один Google-аккаунт.
2. При запуске панель сначала читает серверный документ.
3. Постоянный `onSnapshot` доставляет подтверждённые изменения на все открытые устройства.
4. Пользовательское действие отправляет `update()` только для изменённого Firestore-пути.
5. Одна галочка не отправляет и не заменяет весь список прогресса.
6. Обновление страницы, авторизация и входящий снимок не вызывают обратную запись.
7. Закрытое устройство при открытии получает актуальный серверный снимок и не отправляет старый кэш назад.
8. `localStorage` используется только как последний отображённый кэш и резервная копия.
9. Офлайн-записи удерживает Firestore IndexedDB с `synchronizeTabs: true`; собственной очереди операций у панели нет.
10. Старые облачные документы читаются только для первоначальной миграции, если `default_realtime` ещё не создан.

Код синхронизации находится в `js/app.js` и `js/core/realtime-state.js`. Подробное описание — в `documentation/ARCHITECTURE.md`.

## Сервис скриншотов

Сервис Vercel используется для загрузки оригинальных изображений и формирования общей ссылки отчёта.

- Количество изображений на один пункт не ограничено.
- Максимальный размер одного файла — 15 МБ.
- Поддерживаются PNG, JPG и WEBP.
- Файлы автоматически удаляются через 8 дней.
- В Firebase хранятся только ссылки и метаданные, а не изображения или Base64.

Адрес сервиса: `https://rp-cabinet-proof-service.vercel.app`
