# RP CABINET — TEST v102

## Что изменилось в v102

- Плашка рабочей программы в боковой панели больше не является заглушкой.
- Программа получила название `RP-Helper`.
- Нажатие по плашке сразу скачивает `RP-Helper.zip` из GitHub Release `program-v1.0.0`.
- Для загрузки используется постоянный релиз репозитория `wxzg4bgc6n-code/RP-CABINET-test`.
- Плашка доступна с компьютера и телефона и использует визуал текущей темы панели.

## Сохранено из v101

- Исправлена повторная потеря подключения Google Drive после открытия новой вкладки или перезапуска браузера.
- Действующий Drive access token хранится в локальном кэше только до своего срока окончания и обязательно привязан к Firebase UID.
- Токен автоматически подхватывается другими вкладками панели на том же устройстве.
- При смене Google-пользователя старые токен и идентификаторы папок не используются.
- При обновлении доступа Google получает `login_hint` подключённого профиля и больше не должен повторно предлагать выбор аккаунта.
- После первого разрешения панель помнит подключение отдельно от короткого токена: плашка «Подключить Google Диск» не возвращается только из-за окончания токена, а загрузка и создание отчёта остаются доступными.
- При выходе из профиля Drive-токен полностью удаляется с устройства.

## Обязательная настройка Google Cloud

Файлы v102 готовы, но Google не разрешит работу с Диском, пока API не включён в проекте.

1. Открыть Google Cloud Console и выбрать проект Firebase `rp-cabinet`.
2. Включить **Google Drive API**.
3. В OAuth consent screen → Data Access добавить scope:
   `https://www.googleapis.com/auth/drive.file`.
4. Убедиться, что домен GitHub Pages добавлен в Authorized domains и Authorized JavaScript origins текущего Web OAuth client.
5. В API key, указанном в `js/config/google-drive.js`, разрешить Google Drive API и ограничить использование доменом панели.
6. До публикации OAuth-приложения добавить нужные Google-аккаунты в список Test users.

Подробно: `documentation/GOOGLE_DRIVE_SETUP.md`.

## Синхронизация

После входа через Google единственным источником состояния профиля остаётся:

`users/{uid}/profiles/default_realtime`

Firebase хранит:

- профиль и карьерный контекст;
- галочки прогресса;
- закрепления и премию;
- `fileId`, `resourceKey`, размеры и названия скриншотов;
- идентификатор публичного отчёта;
- метаданные пользовательской аватарки.

Firebase не хранит изображения и Base64. Сами файлы принадлежат пользователю и находятся на его Google Диске.

Модель синхронизации v80 не изменена:

1. `onSnapshot` постоянно доставляет серверные изменения телефону и ПК.
2. Каждое действие обновляет только свой Firestore-путь.
3. Открытие или обновление страницы ничего не отправляет в облако.
4. Закрытое устройство сначала получает серверное состояние.
5. `localStorage` остаётся только кэшем.
6. Access token Google Drive не записывается в Firebase; локальный кэш хранит его только до времени окончания и только для соответствующего UID.

## Скриншоты и отчёты

- PNG, JPG и WEBP;
- до 15 МБ на файл;
- без лимита количества на пункт;
- каждый файл сразу получает закрытую от поиска публичную ссылку;
- публичная ссылка не раскрывает папку или остальные файлы пользователя;
- ручное удаление скриншота из прогресса сразу вызывает Google Drive `files.delete`;
- крестик доступен у каждого скриншота, а кнопка «Удалить все скриншоты» очищает текущий контекст одной операцией;
- удаление скриншота при активном отчёте также удаляет JSON отчёта и отключает публичную ссылку;
- отсутствующий на Диске файл можно убрать из панели без зависания;
- оставленные скриншоты и отчёты автоматически очищаются через 8 дней при следующем подключении Диска;
- удаление отчёта вручную окончательно удаляет его JSON и связанные скриншоты;
- старые ссылки v92 не считаются активными отчётами v102.

## Аватар

- одна активная пользовательская фотография;
- центральное квадратное кадрирование;
- WebP 512×512;
- загрузка открывается карандашом поверх аватара, а не из настроек профиля;
- на ПК карандаш появляется при наведении, на телефоне виден постоянно;
- перед сохранением доступны масштабирование и перемещение кадра;
- новая фотография сначала загружается и синхронизируется, затем старая удаляется;
- аватар не участвует в восьмидневной очистке;
- если пользовательский аватар ещё не загружен, используется фото Google, затем инициалы.
